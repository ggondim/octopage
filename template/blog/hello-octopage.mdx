Octopage builds a fully static site whose content lives in a public GitHub
repository — either as **Discussions** or as **MDX committed to the repo** — and
whose comments are GitHub Discussions threads rendered by giscus.

## The two source modes

<Stack direction="vertical" gap="condensed" padding="none">
  <Box padding="condensed" borderRadius="medium" backgroundColor="subtle">
    <Label size="small">discussions</Label> — write in the GitHub Discussions
    editor. Nothing is committed. The build syncs every discussion down to MDX
    before Astro runs, so component tags in a discussion body still render.
  </Box>
  <Box padding="condensed" borderRadius="medium" backgroundColor="subtle">
    <Label size="small">code</Label> — write `.mdx` under `blog/` or `pages/`
    and preview locally before publishing. The build creates the paired
    discussion that giscus attaches comments to.
  </Box>
</Stack>

Both modes render through the same pipeline, so nothing about a page changes
when you switch between them except where the text is stored.

## Why the Primer components work without hydration

Primer Brand themes through a `data-color-mode` attribute rather than React
context — as of v0.73 no component in the library reads that context. The
layout sets the attribute on `<body>`, so components render to static HTML and
a prose page ships no client JavaScript at all. Only genuinely interactive
components become islands.
